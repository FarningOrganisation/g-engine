# Maintaining the documentation

Documentation lives with the implementation so a change can update code,
tests, docstrings, and guides in one pull request.

## Local commands

From the repository root:

```bash
python -m pip install -e ".[docs]"
python -m mkdocs serve
```

For the same validation used in CI:

```bash
python -m mkdocs build --strict
```

The generated `site/` directory is ignored and must not be committed.

## API reference generation

The build reads `g.__all__` statically and generates one reference page per
export group. mkdocstrings uses Griffe to read Python signatures and docstrings
without starting a game window. No hand-maintained duplicate API list is
needed.

The API navigation is generated by mkdocs-gen-files and mkdocs-literate-nav.
Add or remove a public root export and its reference directive follows
automatically. The special `colors` module includes its named constants.

## Google-style docstrings

```python
def move_to(x: float, y: float) -> None:
    """Move to a world-space position.

    Args:
        x: Horizontal world coordinate in pixels.
        y: Vertical world coordinate in pixels.
    """
```

Use `Args`, `Returns`, `Yields`, `Raises`, and `Attributes` when relevant.
Explain units, coordinate spaces, ownership, callback signatures, and lifecycle
behavior rather than repeating the type annotation in prose.
Do not invent exceptions or guarantees that the implementation does not make.

Examples using names such as `game`, `scene`, or `player` are contextual
snippets unless explicitly introduced as a complete program.

## Publishing to GitHub Pages

1. Push this repository to GitHub with `main` as the publishing branch.
2. In **Settings > Pages**, select **GitHub Actions** as the source.
3. Push documentation changes or run the Documentation workflow.

Pull requests build the site but do not deploy it. Successful builds on `main`
publish through GitHub's Pages artifact/deployment actions.
The deployment job records the resulting site URL.

Set `site_url` in `mkdocs.yml` once the final repository or custom-domain URL
is known. No placeholder GitHub owner is baked into the configuration.
